# 三档快打分 + 纸角二维码 设计稿（2026-11-23）

## 1. 为什么做

商业化路线（`docs/research/2026-11-23-monetization-research.md`、记忆 sumsum-roadmap-2027）里，「家长批改太累」是最大流失风险，也是我们唯一难被免费替代的卖点（批改驱动第二天调整的循环）所在。

现状：只有识字、拼音真正「错哪练哪」；口算不登记、奥数只有「已学」、五个游戏不登记——介绍页「家长回来点一下，第二天按这个排」对它们并不成立。

目标：
1. 家长扫一次码、十几秒点完当天所有纸；
2. 口算、奥数、五个游戏第一次接上「错哪练哪」；
3. 不用 AI、零成本；对错全由家长判断；
4. 留好打分数据，给中期的每周学情邮件、家长看板直接用。

不做：孩子扫码（违背少看屏）；未登录登记；奥数错题原题重出（第一版只到知识点）；识字、拼音的三档（它们的价值在逐字精确）。

## 2. 家长看到的流程

1. 每张**题目页**右上角印约 16mm 的二维码，旁边小字「扫码登记」。屏幕上的纸同样有（屏幕即打印）。答案页、解析页、讲解页不印。
2. 家长扫码（多半用微信）→ 打开 `/mark?id=<纸号>`。没登录 → 网关已有的 `/?next=` 跳登录 → 登录后回到这张纸。登录保持 90 天（server/session.js）。
3. 登记页上半部：这张纸。下半部：「今天还没登记的纸」列表（今天及昨天打印、未登记的），同页依次点完。
4. 每张纸的登记方式：
   | 板块 | 方式 |
   |---|---|
   | 口算、奥数 | 三个大按钮「会了 / 一般 / 不会」；按钮下写标准：会了＝全对或只错 1 题；一般＝错了几题；不会＝错一半以上或做不下去。下面「展开点错题」：逐题点做错的，**展开点过就由系统按错题比例自动选档**（见 4.1），家长不用再选 |
   | 数独、火柴、密码、迷宫、数织 | 「太简单 / 刚好 / 太难」 |
   | 识字（每日卷、周卷、错字卷、检查卷） | 直接在登记页画这张卷的字格，点「没认出」的字 → 复用识字结算（与电脑上登记等价） |
   | 拼音 | 跳回拼音页这张卷（规则复杂：顺的不点 / 提示了 / 没读出 / 停在哪题），拼音页登记区在手机宽度下排顺 |
5. 当天可改，以最后一次为准。识字沿用已有「当天整卷撤销」。
6. 电脑上也能登记：各板块页面上同一套三档 / 点错题组件。
7. 什么都不点：一切照旧；「今天」页提示一句「还有 N 张纸没登记」。

## 3. 数据

### 3.1 纸的记录
每张纸一个同步键 `sumsum:sheet:v1:<id>`（按键合并，电脑新出纸和手机打分不会互相覆盖；同拼音 `sumsum:pinyin:sheet:v1:` 的做法）。

```
{
  id, module,            // kousuan | aoshu | shizi | pinyin | shudu | huochai | mima | migong | zhizhi
  title, date,           // 打印日 YYYY-MM-DD
  printedAt,             // 毫秒
  units: [ { key, label } ],   // 要打分的单位：口算/游戏 1 个（整张）；奥数=本课或复习卷里的每一课；识字/拼音为空
  items: [ { key, label, unit, cat } ],  // 可点错的题：口算题面 + 分类；奥数题号 + 所属课；识字为字
  ref,                   // 回到原板块需要的东西：识字 paper 序号、拼音卷号、游戏关卡等
  rating: { <unitKey>: { level: 'good'|'ok'|'bad', auto: bool, at } } | null,
  wrong: [ itemKey ] | null,
  appliedAt               // 打分规则已作用到板块进度的时间，防重复作用
}
```

1. **id**：板块 + 内容指纹（板块、设置、种子、日期）哈希成 6 位短码。同一张纸重渲染 id 不变；「换一批」才是新纸。
2. **何时写**：`beforeprint`（Ctrl+P、打印按钮、「今天」页 `#print` 都会触发）时写入；只渲染不打印不写，避免攒垃圾。同步引擎改动后约 2 秒推上云（js/sync.js DEBOUNCE）。
3. **清理**：只留最近 60 天；超出的在任意页面加载时顺手删。
4. 手机打开登记页：sync.init 先拉；本地仍没有这张 → 提示「电脑那边还没同步好，几秒后点刷新」+ 刷新按钮。

### 3.2 二维码
1. 内容：`location.origin + '/mark?id=' + id`（换域名自动跟随）。
2. 生成：vendor 一个 MIT 协议的纯 JS 二维码库（qrcode-generator, Kazuhiko Arase）到 `js/vendor/`，附 LICENSE，本地生成 SVG，不依赖外网。纠错级别 M。
3. 打印：黑白、16mm 左右、放在纸张页眉区不压题；各板块现有页眉（日期____ 姓名____ 一行）右侧。

## 4. 打完分怎么作用到下一张（纯函数，放 `js/sheets-core.js`，node 可测）

### 4.1 自动定档
展开点了错题时：错 0–1 题 → 会了；错题 ≥ 一半 → 不会；其余 → 一般。家长仍可手动改档（auto 记为 false）。

### 4.2 口算
1. 每题记分类 `cat`：进位加 / 退位减 / 不进退位 / 乘 / 除 / 混合（由题面 tokens 算出）。
2. 下一张（只作用于下一张，**不改用户设置**）：
   1. 点过的错题（最多 5 道、仍在当前设置范围内）原样混进下一张；
   2. 错题里进位/退位占一半以上，或整张打「不会」→ 下一张临时用 `carrymore`（当前为 random / nocarry 时）。
3. 升档只提示：同一预设连续两张「会了」→「今天」页口算卡提示「可以升到下一档：<下一个预设>」，点一下才换（按 settings.js PRESETS 顺序）。
4. 实现：generator 加可选参数「必含题」「临时进位模式」，不传时行为不变。

### 4.3 奥数（每课一个单位；复习卷里每课各一个）
| 档 | 作用 |
|---|---|
| 会了 | 自动标「已学」（sumsum:aoshu:learned:v1）；若在待复习里则移出 |
| 一般 | 标「已学」+ 加入待复习 |
| 不会 | 不标已学；「今天」页奥数卡建议「这一课再练一张」（aoshu-batch 换种子出新一批） |
| 点过错题 | 错题所属的课加入待复习 |

待复习存 `sumsum:aoshu:review-due:v1`（课 id 数组）。满 3 课时，「今天」页奥数卡给「打印复习卷（待复习 N 课）」，点了把 reviewTopics 设为这些课。与 reviewTopics、已学互不干扰的原则（aoshu-settings.js 注释）保持不变。

### 4.4 五个游戏
1. 太简单 → 下一张自动升一档；太难 → 降一档；刚好 → 不变。到顶/到底不动。
2. 档位：火柴、密码、迷宫、数织为 L1–L4；数独为提示数（按 shudu-core CLUE_RANGE 每次加减一步，盘型不自动换）。
3. 自动改动写进该游戏设置，并在「今天」页卡片写明「按上次反馈升到第 3 关」+「撤销」（撤销恢复改动前的值）。

### 4.5 识字、拼音
识字：登记页调用 shizi-mark 现有的点选与 `settle`，等价于在识字页登记。拼音：不经 sheets-core，跳回拼音页。

## 6. 错误与边界

1. 手机没登录 → 登录后回原纸（网关已有）。
2. 记录还没同步上来 → 提示 + 刷新按钮，不报错。
3. 别的账号扫码 → 本地无此纸，提示「这张纸不是这个账号打印的」。
4. 同一张纸打印两份（游戏对战）→ 同一 id，登记一次即可。
5. 打完分后又改档 → 以最后一次为准；已作用过的（appliedAt）先撤回再重新作用（游戏、奥数）；口算只影响下一张，下一张已生成则不追改。
6. 旧数据：没有纸记录的老打印不受影响。

1. `tools/check-sheets.js`：纸号稳定性、60 天清理、自动定档边界、口算分类与必含题、奥数三档作用与待复习、游戏升降到顶到底、撤销。
2. 现有 check-*.js 全绿（generator 不传新参数时出题不变——同种子同输出对比）。
3. 浏览器全流程（tools/ 下 playwright 脚本）：电脑出口算、奥数、识字、火柴各一张并打印 → 手机尺寸打开 `/mark?id=` → 先未登录跳登录再回来 → 打分 / 点错题 → 列表里连续登记其余 → 回电脑看下一张按规则变化；拼音扫码跳转后手机截图。
4. 打印导出 PDF：二维码位置不压题、清晰；手机实拍扫码可识别。
5. 微信内置浏览器实测一次（站长手机）：扫码 → 登录 → 回到这张纸。
