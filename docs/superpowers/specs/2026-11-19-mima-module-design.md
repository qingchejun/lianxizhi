# 「密码」板块设计（密码推理练习纸）

日期：2026-11-19
状态：设计已与站长口头确认（单独板块 + 首版只做打印），待书面复审

## 1. 背景与目标

站长的儿子上一年级，想要"猜密码"式推理题（给出若干行猜测 + 线索，推出唯一密码）。
市面上的题（如 4 位 + 复合文字线索）对一年级直接上手太难——瓶颈往往不是推理，
而是读不懂"两个号码正确，只有一个位置正确"这种句子，读不懂就蒙，蒙就劝退。

目标：做一个**循序渐进、可打印**的密码推理板块：

- 第 1 关的目标是"第一次就做得出来"：用数点子代替读句子，先尝到"我推出来了"的甜头；
- 逐级过渡到书上常见的文字线索题；
- 质量红线与数独板块一致：每题唯一解、只靠排除能解到底，不需要"假设试试"。

使用者场景沿用全站惯例：打印出来父子同题对战（打印份数 = 2 时同题连印两份）。

## 2. 结构决策

**单独做第 6 个板块**（不建「数字游戏」容器）：

- 完全照数独的路子：自己的页面 + 自己的 js/css，现有文件一行不动；
- 数独入口零变化（天天用的功能不加点击）；
- 以后真出现第 3 个游戏再考虑收拢分组——导航由 `tools/rail.py` 生成，重跑即可，页面网址不用动。

板块名「密码」，页面 `mima.html`，导航放在数独后面。图标用锁。

## 3. 题目模型

一个模型，两种皮肤：

- **密码**：N 位**不重复**数字（N ∈ {3, 4}），取自数字池 pool。
- **线索行**：一行猜测 g₁…g_N，附反馈 (a, b)：
  - a = 数字对**且位置也对**的个数（●）
  - b = 数字对**但位置不对**的个数（○）
  - 密码不重复 ⇒ 每行反馈由密码唯一真算得出，线索永不说谎。
- **呈现**：
  - 关卡 1/2 用**点子**：行尾印 ●×a ○×b，**固定先 ● 后 ○**（顺序打乱会泄露对应关系）；
  - 关卡 3/4 用**文字**，同一信息的句子化：
    - (0,0) →「这些号码都不在密码里」
    - (a,0) →「只有 a 个号码正确，位置也对」
    - (0,b) →「有 b 个号码正确，位置都不对」
    - (a,b) →「有 a+b 个号码正确，只有 a 个位置正确」
    - 数字用阿拉伯数字（一年级读数字没问题，难的是句子结构）。

## 4. 关卡

难度不是连续滑块而是**关卡制**：线索的"样子"在变（点子 → 文字），推理方法不变。
参数是代码里的常量，给儿子试做后一行就能调。

| 关卡 | 名称 | 位数 | 数字池 | 线索行数 | 线索限制 | 呈现 | 卷面辅助 |
|---|---|---|---|---|---|---|---|
| L1 | 点点入门 | 3 | 1~6 | 4~5 | 每行 b=0（只有 ● 和全错） | 点子 | 划掉数字带 + 图例 |
| L2 | 双色点 | 3 | 1~9 | 4 | ●○ 混合 | 点子 | 划掉数字带 + 图例 |
| L3 | 读题破译 | 3 | 0~9 | 4 | 无 | 文字 | 无 |
| L4 | 大侦探 | 4 | 0~9 | 3~4 | 无 | 文字 | 无 |

- **划掉数字带**：把数字池印成一排小格子，推理时把"不在密码里"的数字划掉——第 1 关的核心动作。
- **图例**（印在卷面上）：● = 数字对，位置也对；○ = 数字对，位置不对；没有点 = 这行里没有密码的数字。

## 5. 生成与验收红线

与数独"logicSolve 是挖洞的验收标准"同构，**求解器就是出题的验收标准**：

1. 随机定密码 C（池内不重复）。
2. 在关卡行数区间内随机定一个目标行数，按该行数撒线索行：每行从池随机取 N 个不重复数字；行与行不重复、行 ≠ 密码；L1 的行必须 b=0，否则重撒该行。
3. 每行按密码真算 (a, b)。
4. **验收两条，全过才算一道合格题**：
   - **唯一解**：枚举池内全部 P(pool, N) 个排列（最坏 P(9,4)=3024，瞬时），与所有行的 (a,b) 一致的必须恰好 1 个；
   - **排除可解**：第 6 节的求解器能推到底（不许假设试探）。
5. 不过关 → 换一批行重撒（不是累加，避免线索越堆越啰嗦）；同一密码重撒超过 20 次仍不过 → 重开新密码。

## 6. 逐步排除求解器

只会"孩子也跟得上的动作"。状态：每位一个候选集 cand[pos]（初始为全池）；
数字"存活" = 还出现在某位的候选里。规则迭代到不动点：

- **R1 划数字**（全错行）：行 (0,0) → 行内数字从所有位划掉。
- **R2 行收编**：行内存活数字个数 == a+b → 这些数全在密码里。
- **R3 单一定位**：确认在密码里的数 d，可能位置只剩 1 个 → 定位；定位后从其他位划掉 d，该位的其余候选全划掉（不重复约束）。
- **R4 行位置名额**：行内"确认在密码里"的数中，还可能落在自己行位置的集合 T：
  - |T| == a → T 里全部定位（"位置对的只能是它"）；
  - a == 0 → T 里的数从自己的行位置划掉（"位置都不对"）。
- **R5 池收紧**：存活数字个数 == 未定位位数 → 存活的全在密码里；某位候选只剩 1 个 → 定位。

全部定位 = 解出。跑不到底 = 这题不合格，换题（见第 5 节）。
特例：某行恰为密码（a=N, b=0）等于直接报答案，生成时排除。

## 7. 分步解析

求解器推理时记轨迹，答案页按序号列**人话步骤**，每条对应一次规则触发，例如：

> ① 第 1 行全错 → 划掉 9、3、4、1
> ② 第 4 行三个数都活着、名额也满 → 2、5、8 都在密码里
> ③ 位置都不对 → 2 不在第 1 位，5 不在第 2 位，8 不在第 3 位
> ……
> ⑦ 密码是 5 8 2 7

末条必须是密码本身。L1 的步骤尤其要用短句。

## 8. 页面与版面

- `mima.html` 照数独骨架：rail + work-head（标题 / 重新生成 / 打印）+ preview + panel；固定 A4 纵向。
- **题卡**：关卡徽章（第 1 关 · 点点入门）+ 题号；线索行表（格子数字，行尾点子或文字）；密码框 □□□；L1/L2 附划掉数字带与图例。
- **每页题数按关卡固定**（初值：L1/L2 每页 2 道、L3 每页 3 道、L4 每页 2 道），排版校验兜底；题量默认 4 道，可调 1~12。
- **打印份数 = 2 → 同题连印两份**（照数独，对战才有意义）。
- **答案页**（可选，末尾集中）：每题密码 + 分步解析，多题排两栏。
- 标题自动生成（如「密码推理 · 第 2 关 双色点」），可自定义——全站惯例。

## 9. 设置与网址

- 面板项：关卡（四选一）、题量、打印份数、附答案页、标题。样式同数独面板。
- 随机源 mulberry32 **自抄一份**（数独先例：不为 8 行代码引入跨模块加载依赖）。
- 设置 + 种子写进网址：刷新/转发同一张卷子；网址带参数时忽略 localStorage；存储键前缀 `mima:`。

## 10. 校验脚本 `tools/check-mima.js`

数独的教训（校验器比生成器更容易写错）全盘照搬：

- **独立第二实现**：枚举计数器与 (a,b) 计算另写一份，与 core 互为对证；
- **先自检**：内置几道手工题（已知唯一/已知多解/已知不可解），校验器自身不过就 exit(2) 并明说"是校验器坏了"；
- **扫描**（每关 ≥300 局）：唯一解严格成立、求解器可解、解析末条 = 密码、行数在关卡区间、L1 每行 b=0、位数/数字池符合关卡、行不重复、行 ≠ 密码；
- **排版**：按 180×225 版心（与渲染层**故意不共用** MM 常量，互为对证）重算每关 × 每页题数的占地，断言放得下。

## 11. 首版范围外

- 在线玩（屏幕点选作答）——儿子喜欢再加；
- 「今天」首页集成——游戏不是每日任务；
- 密码含重复数字（对一年级太难）；
- 位数 2 / ≥5、面板自定义关卡参数（固定四关）。

## 12. 整体验收

1. `python3 tools/rail.py` 重跑后，六个页面的导航都有「密码」且当前页高亮正确；
2. 默认设置导 PDF：页数符合设计、无空白页、无内容溢出（导 PDF 数页数 + 转图目检，数独的三个 CSS 坑都是这么抓到的）；
3. `node tools/check-mima.js` 全绿；`check-shudu.js`、`check-today.js` 等现有校验不回归；
4. 人工做一遍 L1 一道题，对照答案页分步解析核对（dogfood）。
